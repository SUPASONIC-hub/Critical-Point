# CRITICAL POINT (임계점)

Tak'n Roll 제작, SUPASONIC 기획·개발.

**판돈을 올릴수록 벽이 가까워진다.** 기업·금융 미스터리이자 푸시 유어 럭 게임입니다.
플레이어는 3년 전 승인 서류 한 장에 혼자 반대 의견을 썼다가 KD금융그룹 지하 연구소 트리거랩으로
밀려난 분석관이 되어, 그 대출이 무너지는 72시간부터 본사 33층의 빈 서명란까지 열 개의 사건을
지납니다. 매 장면 카드 한 장을 걸고 확정할지 더 밀어붙일지 결정합니다. 밀 때마다 판돈은 1.5배
이상 불어나고, 보이지 않는 벽에 닿으면 사건 판돈 전부와 카드의 이득이 사라집니다. 그리고 그
판단은 다음 판의 규칙을 부숩니다.

## 이야기

열 개의 사건은 각각 다른 곳에서 벌어지지만 하나의 사슬입니다. 3년 전 KD은행이 물류 플랫폼
플로우온에 내준 310억 대출이 그 사슬의 첫 고리입니다.

| 사건 | 무대 | 사슬에서의 자리 |
|---|---|---|
| 01 72시간 | 플로우온 본사·물류 현장 | 그 대출이 실제로 무너진다 |
| 02 가짜 신호 | 트리거랩 보안 감사실 | 서류를 덮으려다 계약직 한 명이 지목된다 |
| 03 경쟁자의 반격 | 세움테크 입찰장 | 손실을 다른 회사 장부로 옮기는 통로 |
| 04 치러야 할 대가 | 돌봄 플랫폼 온새 | 옮긴 손실이 돌봄 시간 3%로 나타난다 |
| 05 범인은 없었다 | 돌봄 배차 복구 통제실 | 아무도 빌린 적 없는 사람들에게 청구된다 |
| 06 같은 방의 사람 | 트리거랩 4층 | 같은 사슬이 옆자리 동료를 부순다 |
| 07 되갚는 자리 | 감사팀 서고·강서지점·헌책방 | 이번엔 당신이 옮겨진다. 48시간 안에 누가 손을 내미는가 |
| 08 돈의 흔적 | 강원 영동지점·경포 펜션·청담동 갤러리 | 좌천된 창구에서 대출의 돈이 윤상혁의 가족에게 흘러간 흔적을 찾는다 |
| 09 두 장의 손익계산서 | 플로우온 채권단 회의실·풀필먼트센터 | 처음 무너진 회사를 살리면서, 무너뜨린 사람을 같은 테이블에서 벌한다 |
| 마지막 빈 서명란 | 본사 33층 그룹전략실 | 3년째 비어 있는 그 칸의 주인을 만난다 |

앞의 여섯 사건은 당신이 무엇을 포기하는지 묻습니다. **사건 07은 처음으로 당신이 부탁하는 쪽이
됩니다.** 위원회가 끝난 다음 날 발령서가 도착하고 -- 징계가 아니라 인사라 사유도 이의 절차도
없습니다 -- 48시간 뒤면 파일은 여기 남고 당신은 240km 밖에 있습니다. 남은 이틀에 모아야 하는
것은 수첩 한 권, 창구 서류 뒷장, 전산에 없는 종이 한 장, 그리고 한 사람만 할 수 있는 진술입니다.
넷 다 주는 사람이 대가를 치르고, 그중 셋은 그래도 내어 줍니다.

**사건 08과 09는 시즌의 2막입니다.** 같은 집념이 서로 다른 감정에서 깨어난다는 이 게임의 가설을
두 사건이 나눠 맡습니다.

- **사건 08 「돈의 흔적」은 복수심의 지성입니다.** 좌천된 강원 영동지점의 휴면 계좌(오래 거래가 끊긴
  계좌) 하나가 분기마다 자문료를 받아 청담동 갤러리로 보냅니다. 오진우는 아버지에게 들은 말로 추적을
  시작합니다. 윗사람도 결국 사람이고, 사람은 욕망을 갖고, 욕망은 돈을 쓰고, 돈은 흔적을 남긴다.
  흔적은 진짜입니다. 질문은 그 흔적을 쫓는 손이 쫓는 대상과 닮아도 되는가입니다. 미끼를 놓을지,
  법원에 보전 신청(재산을 못 옮기게 묶어 두는 절차)을 낼지, 흔적표를 누구 손에 쥐여 줄지 정합니다.
- **사건 09 「두 장의 손익계산서」는 애정과 책임의 지성입니다.** 플로우온이 다시 72시간 앞에 서고,
  이번 안건은 청산(회사를 정리해 없애는 절차)입니다. 청산을 미는 브릿지은행의 심사역은 가업을 거절한
  창업주의 장남 권도현이고, 그는 계산서로 적을 수 없는 도움은 받지 않습니다. 회사를 살리는
  계산서(출자전환, 고용 승계)와 무너뜨린 사람을 벌하는 계산서(배임·횡령·분식회계 고발, 금융감독원
  정기검사에 맞춘 제보)를 한 테이블에 올릴지가 사건의 마지막 질문입니다. 구제 없는 처벌은 1,140명에게
  두 번 벌을 주고, 처벌 없는 구제는 덮어 주기가 됩니다.

등장인물은 전부 이 은행에서 일하거나, 이 은행에 밀려난 사람들입니다. 한서윤(트리거랩 실장)은
3년 전 당신의 반대 의견을 반려한 사람이고, 도윤하(현장 담당)는 그 대출을 창구에서 판 사람이며,
오진우(경쟁 분석관)는 승인을 하루 늦춰 밀려난 지점장의 아들입니다. 반재욱(감사팀 조사역)은
자기가 자른 사람의 이름을 전부 수첩에 적어 둡니다. 임경수는 전산에 없는 종이 원본을 4년째
들고 있는 퇴직 심사팀장이고, 윤상혁 상무는 그 서명란을 비워 둔 사람입니다. 2막에는 세 사람이
더 들어옵니다. 나준혁(영동지점장)은 세 번 반려한 보고서를 30년 만에 자기 도장으로 되갚고,
권도현(브릿지은행 심사역)은 모든 호의를 손익계산서로 바꿔 받으며, 강태민(플로우온 야간조 반장)은
사건 01의 새벽에 컵라면을 뜯어 주던 그 사람입니다.

금융 용어는 지금 한국 은행에서 실제로 쓰는 말로 적었습니다. 여신·융자·품의·결재·기안 같은 일본식
한자어 대신 대출·승인·작성을 쓰고, 인물·회사 이름도 지금 들어도 어색하지 않은 이름을 씁니다. 처음
나오는 어려운 말은 괄호 안에 쉽게 풀어 설명합니다(예: 부채비율, 산식, 엠바고, 선순위 담보, 출자전환).

React 19 + Vite 단일 페이지 앱이고, 서버 없이도 완결됩니다. Supabase는 원격 랭킹과 플레이테스트
텔레메트리에만 쓰이는 선택 사항입니다.

## 무엇을 위한 게임인가

원래 질문은 저장소 이름 그대로입니다: **"내 창의성은 언제 터지는가."** 임계점은 그 질문을
플레이로 바꾼 실험입니다. 사람의 판단은 압박이 전혀 없을 때도, 압박에 짓눌릴 때도 얕아집니다.
그 사이 어딘가 — 판돈이 커지고 시계가 줄어드는데도 아직 생각할 여유가 남아 있는 구간 — 에서
사고가 가장 깊어진다는 가설을, 플레이어가 직접 밀어붙이고 멈추는 행동으로 측정합니다.

- **플레이어에게는** 정답 없는 기업·금융 위기 열 건을 지나며 "나는 어디까지 밀고, 무엇을
  먼저 지키는 사람인가"를 확인하는 판단 스릴러입니다. 선택은 사건을 끝내지 않고 다음 판의 규칙을
  바꾸므로, 한 시즌이 끝나면 자기 판단 습관이 결말과 리포트로 남습니다.
- **만든 사람에게는** 플레이테스트 도구입니다. 어떤 조건에서 즉답 대신 근거를 찾고, 선택지 밖의
  문장을 쓰고, 무너진 뒤 회복하는지를 익명 텔레메트리(동의한 경우에만)로 모읍니다. 이야기의
  마지막 사건은 이 구조 자체 — 사고를 깨우는 조건은 조종 가능한 조건이기도 하다 — 를 되묻습니다.

질문을 한 줄로 줄이면 **"나는 얼마나 똑똑한가"가 아니라 "나는 언제 똑똑해지는가"** 입니다. 이 게임의
가설은 강한 감정이 지성을 방해하는 것이 아니라 방향을 정한다는 것입니다.

> 감정의 방아쇠 → 집념 → 멈추지 않는 생각 → 지성 → 자본과 조직을 움직임 → 현실의 변화

애정은 사람을 살리는 쪽으로(구제), 복수심은 약점을 찾는 쪽으로(교정), 책임은 장부를 맞추는
쪽으로(회생) 같은 집념을 겨눕니다. 사건 08과 09가 이 셋을 정면으로 다루고, 리포트의 `판단 DNA`는
이번 판에서 가장 오래 남은 트리거 묶음을 **생각이 깨어나는 조건**(애정형·복수형·책임형·탐구형)으로
이름 붙여 돌려줍니다.

## 어떻게 플레이해야 하나 (전략)

점수는 두 층입니다. **테이블**에서는 칩을 금고로 옮기는 푸시 유어 럭을 하고, **사건 리포트**에서는
그 과정이 얼마나 깊은 판단이었는지를 0~100의 버스트 점수로 매깁니다. 둘은 서로를 끌어당깁니다.

**테이블에서 살아남기**

- **금고가 유일한 안전지대입니다.** 벽은 이번 사건 판돈만 가져가고 금고는 못 건드립니다. 크게
  한 번 터뜨리기보다 여러 번 챙기는 쪽이 시즌 전체로는 강합니다.
- **심박을 읽으십시오.** 벽의 위치는 끝까지 나오지 않고, 심박이 빨라질수록 벽이 가깝다는 신호입니다.
  다만 오차가 있으니 벽 구간에 들어서면 한 번 더 미는 것 자체가 도박입니다.
- **박자에 맞춰 미십시오.** PERFECT/GOOD 콤보가 판돈에 최대 ×1.5 GROOVE를 붙이지만, 박자를 놓치면
  콤보가 끊기고 시계 1초를 잃습니다. 박자는 벽을 옮기지 않으므로 "박자가 좋으니 한 번 더"는 함정입니다.
- **다음 판을 생각하고 확정하십시오.** 한 번도 밀지 않고 확정하면 가장 좋은 카드가 봉인되고(COLD FEET),
  너무 높은 배율로 확정하면 열기와 시간을 빚집니다(HEAT DEBT). 방금 가장 크게 태운 자원은 다음 판에서
  1.5배로 청구되니(FRACTURE) 같은 자원만 계속 태우지 마십시오. 시간 초과는 심박을 없앱니다(SILENCE).
- **도구는 약점을 메우는 쪽으로 고르십시오.** 자주 터진다면 냉혈·방열판, 박자가 어렵다면 메트로놈처럼,
  드래프트 세 장 중 지금 시즌의 사고 방식에 맞는 것을 고르는 편이 수치가 큰 것보다 낫습니다.

**높은 버스트 점수를 받기**

버스트 점수는 테이블 금고가 아니라 판단의 결을 봅니다. 결과 화면의 점수 칸과 같은 항목이며, 비중은 다음과 같습니다.

| 항목 | 비중 | 올리는 법 |
|---|---|---|
| 기준 유지 | 28% | 압박이 올라간 장면에서도 앞서 지킨 방향을 뒤집지 않는다 |
| 관점 전환 | 20% | 추론·위험 회피·재구성·버티기를 한 가지로만 반복하지 않는다 |
| 구조 재설계 | 20% | `직접 말한다`로 이해관계자·조건·근거·실패 가능성을 적고, 숨은 기록을 연다 |
| 압박 대응 | 16% | 위험을 무조건 피하기보다, 치솟은 압박을 다음 장면에서 회수한다 |
| 사고 리듬 | 8% | 즉답도 방치도 아닌, 읽고 결론까지 밀어낸 시간대에 누른다 |
| 장면 챌린지 | 8% | 장면마다 걸린 챌린지 조건을 맞추고, 연속으로 이어간다 |
| 즉답 패널티 | 최대 −18 | 자유입력 없이 2초 이내로 누르는 선택 한 번마다 −5 |

S(88+)·A(72+)·B(52+)·C 랭크가 여기서 나옵니다. 요약하면 **빨리 누르는 사람이 아니라, 흔들리는
판에서 자기 기준을 지키면서도 판 자체를 다시 짜는 사람**이 높은 점수를 받습니다. 자원(시간, 현금,
믿음, 공정함, 사람 피해, 피로)의 균형과 BUST 기록은 열 번째 사건 뒤 9가지 결말 중 무엇에
도달할지를 정합니다.

## 무엇으로 경쟁하나

- **랭킹 보드** — 완료한 사건의 버스트 점수(0~100)로 순위를 매깁니다. 동점이면 랭크 → 구조 재설계
  → 압박 대응 → 관점 전환 순으로 가립니다. 한 런(run)은 가장 좋은 기록 하나만 오르고, 시즌을 끝낸
  기록이 중간 기록보다 항상 앞섭니다. 같은 런을 여러 번 제출해도 순위를 도배할 수 없습니다.
- **리그** — 플레이 스타일로 나뉩니다. 자유입력으로 판을 다시 짠 **REFRAME LEAGUE**(BOARD BREAKER),
  압박 회수가 두드러진 **RISK LEAGUE**(RISK CUTTER), 구조적 사고가 높은 **SYSTEM LEAGUE**(SYSTEM
  THINKER), 현장 판단형 **FIELD LEAGUE**(FIELD DECIDER). 같은 점수라도 어떤 방식으로 도달했는지가 함께
  표시됩니다.
- **로컬과 원격** — 서버가 없으면 이 브라우저의 기록끼리 겨루는 로컬 보드가, Supabase가 설정되어
  있으면 공개 보드가 뜹니다. 공개 보드의 다른 참가자는 이름 없이 스타일과 런 라벨로만 보이고, 서버는
  완주 점수의 형태를 검증한 뒤에만 기록을 받습니다.
- **자기 자신과의 경쟁** — 시즌 로드맵, 도구 도감(시즌을 리셋해도 남음), 9가지 결말, NEW GAME+가
  재도전 동기입니다. 결과 화면의 `이 사건 다시 도전`(`R`)은 같은 사건을 다른 기준으로 다시 밀어볼
  때 씁니다.

## 게임

- **읽기 단계** — 장면이 열리면 시계가 멈춘 채 브리핑이 펼쳐집니다. 어느 방인지, 여기까지 온
  경위가 무엇인지, 사건 팩트 네 줄이 무엇인지 다 읽고 나서 `판 열기`(`Space`)를 누르면 그때부터
  45초가 흐릅니다. 카드는 그동안 보이지만 걸 수는 없습니다. 판이 열린 뒤의 규칙은 예전과 똑같고,
  달라진 것은 읽는 시간이 시계 밖으로 나왔다는 것뿐입니다. 덕분에 리포트의 `사고 리듬`도 읽는
  시간이 아니라 판단한 시간만 재게 됐습니다.
- **테이블** — 한 장면이 한 화면입니다. 위에서부터 판돈(칩 × 배율), 열기 게이지와 벽이 그려진
  구간, 장면의 질문, 카드 패, 그리고 `밀어붙인다` / `확정` 두 버튼. 390x844 휴대폰, Pixel 7,
  1280x720 데스크톱, 1366x768 노트북에서는 229개 장면 모두 규칙이 쌓인 판에서도 스크롤 없이 카드가
  액션 바 위에 들어갑니다. 넓은 화면은 왼쪽에 읽을 것, 오른쪽에 카드 패를 두는 두 칸 배치입니다.
- **카드** — 선택지 하나가 카드 한 장입니다. 카드는 칩(이득)과 가장 크게 태우는 자원만 보여줍니다.
  `직접 말한다`는 문장을 쓰는 와일드 카드이고, 시계는 쓰는 동안에도 흐릅니다.
- **밀어붙이기** — 누를 때마다 열기가 7~15 오르고 배율은 열기 11마다 두 배가 됩니다. 벽은
  표시된 구간 어딘가에 있고 정확한 위치와 확률은 나오지 않습니다. 심박만이 벽을 가리키는
  계기이며, 그마저 오차가 있습니다. 가만히 있어도 시계가 열기를 올리고, 시간이 끝나면 터집니다.
- **박자** — 심박이 곧 테이블의 리듬입니다. 밀어붙이기 버튼 위의 고리가 다음 심박에 맞춰 닫히고,
  박자에 맞춰 누르면 PERFECT/GOOD 콤보가 쌓여 판돈에 GROOVE 보너스(최대 ×1.5)가 붙습니다. 박자를
  놓치면(SLIP) 콤보가 끊기고 시계 1초를 잃습니다. 박자는 벽의 위치나 열기 폭을 바꾸지 않습니다.
  확정하면 콤보가 다음 판으로 이어지고, BUST는 판돈과 함께 콤보도 가져갑니다.
- **도구 드래프트** — 사건이 닫히면 다음 사건의 첫 테이블에서 도구 3개 중 하나를 고릅니다(`1`~`3`,
  `Esc`는 건너뛰기). 도구는 시즌이 끝날 때까지 규칙 하나를 바꿉니다: 여진을 식히는 냉혈, 열 빚을
  줄이는 방열판, 봉인을 일찍 여는 락픽, 균열 청구를 줄이는 부목, 박자 판정을 넓히는 메트로놈. 콤보 8,
  판돈 5,000 이상의 BUST, ×64 확정, SILENCE 같은 위업은 앙코르·보험·하이롤러·청진기를 도감에
  해금하고, 도감은 시즌을 리셋해도 남습니다. 드래프트가 떠 있는 동안 시계는 멈춥니다.
- **BUST** — 벽에 닿으면 이번 사건에 걸린 판돈이 0이 되고, 카드는 이득 없이 비용만 치릅니다.
  카드를 고르지 않았다면 회의실이 가장 비싼 카드를 대신 고릅니다. 사건이 닫힐 때 판돈은 금고로
  옮겨지고, 금고는 벽이 가져가지 못합니다.
- **다음 판의 붕괴** — 모든 결정이 다음 판의 규칙을 바꿉니다. BUST 후엔 카드가 뒤집히고 벽이
  가까워지며 열기가 22에서 시작합니다(BLACKOUT, AFTERSHOCK). 시간 초과는 심박을 없애고 시간을
  30초로 줄입니다(SILENCE). 높은 배율로 확정하면 열기와 시간을 빚지고(HEAT DEBT), 한 번도 밀지
  않고 확정하면 가장 좋은 카드가 봉인됩니다(COLD FEET). 연속으로 크게 챙기면 칩과 열기가 함께
  커지고(OVERCLOCK), 방금 가장 크게 태운 자원은 다음 판에서 1.5배로 청구됩니다(FRACTURE).
- **자원과 결말** — 시간, 현금, 믿음, 공정함, 사람 피해, 피로는 여전히 이야기의 축이고, 결말은
  자원과 시즌의 BUST 기록을 함께 읽습니다. 리포트의 `테이블 장부`가 금고, 최고 배율, BUST, 잃은
  판돈을 보여줍니다.

- **이야기와 좌표** — 장면마다 어느 건물의 어느 방인지와 마감까지 남은 시간이 화자 위에 한 줄로
  붙고, 카드 위의 질문은 그 장면이 실제로 묻는 것을 말합니다. 라우트가 갈리면 장면은 쓰인 순서대로
  재생되지 않으므로, 모든 장면은 앞 장면에 기대지 않고 스스로를 설명합니다(`src/nodes/sceneContext.js`).
  접힌 `사건 브리핑`에는 여기까지 온 경위와 사건 팩트가 들어 있습니다.
- **장면 그림** — 229개 장면 전부가 자기 방 그림을 가집니다. 파일로 싣는 대신 장면이 이미
  말하고 있는 `place`와 `phase`에서 그려내므로(`src/scenePlate.js`), 내려받을 바이트가 없고
  장면을 다른 건물로 고쳐 써도 그림이 따라옵니다. 옥상·거리·물류 현장·통제실·서고·복도·회의장·
  은행 창구·바닷가·갤러리·책상 열한 가지 방이 있고, **방마다 사람이 들어 있습니다** -- 화자가 서 있을 자리에
  실루엣이 놓이므로 도면이 아니라 장면으로 읽힙니다. 빛의 색은 건물이 정합니다. 트리거랩과
  강서지점과 헌책방이 서로 다른 색으로 켜지므로, 시즌이 어디로 이동했는지가 날짜 줄을 읽기 전에
  보입니다. 화자 줄 뒤에 깔리고, `사건 브리핑`을 펼치면 또렷한 판으로 한 번 더 나옵니다. 그림은
  멈춰 있지 않습니다. 먼 배경이 천천히 흐르고, 방의 핵심 불빛이 숨 쉬듯 깜빡이며, 낮에는 먼지가,
  자정 넘은 바깥에는 비가 내립니다. 화면이 많은 방에는 주사선이 지나가고, 압박이 걸린 장면은 붉은
  테두리가 맥박처럼 뛰며, 브리핑 속 그림은 아주 느리게 다가옵니다. 모든 움직임은 장면 id로 정해져
  같은 장면은 늘 같은 모습이고, 모션 줄이기 설정에서는 완성된 정지 그림으로 멈춥니다.
- **막간** — 사건이 닫히면 리포트에 베팅도 시계도 선택도 없는 장면이 하나 붙습니다. 컵라면, 문자
  한 통, 자판기 앞의 안 웃긴 농담, 같은 가자미 사진 서른 장, 계산으로 정한 축가 부탁 같은 것들입니다.
  열 개의 사건이 같은 톤으로 이어지지 않게 하는
  자리이고, 사건이 다루지 못하는 인물의 뒷이야기가 여기서 이어집니다.

### 키보드

| 키 | 동작 |
|---|---|
| 숫자 키 | 카드 걸기 (드래프트 중에는 도구 고르기) |
| `Esc` | (드래프트) 도구 없이 진행 |

| `P` / `Shift+P` | 저장 / 저장 후 나가기 |

### 데이터와 접근성

- 브라우저 자동 저장, 완료 기록 JSON 내보내기, 로컬 랭킹은 서버 없이 동작합니다.
- 일반 저장과 별도로 최근 5개 복구 슬롯을 유지하며, 장면 이동·사건 완료·에러 같은 체크포인트에서만
  만듭니다. 저장된 사건과 장면이 어긋나면 해당 사건 시작 장면으로 보정하고 복구 알림을 남깁니다.
- 실명, 연락처, 회사명을 감지해 익명화를 돕고, 분석관 이름과 자유입력 길이를 제한합니다.
- 장면·엔딩·초상화는 WebP로 제공하며 480/960px 변형을 함께 둡니다. 키 비주얼만 `<picture>`와
  `image-set`의 JPEG 대체본을 갖습니다.
- 배경음은 사용자 제스처 이후 장면 분위기에 맞춰 재생됩니다. 결정 창에는 벽까지의 거리로 빨라지는
  심박, 열기로 열리는 드론, 밀 때마다 반음씩 오르는 칩 소리, BUST의 파열음이 붙습니다. 모든 큐는
  `acquireCueRuntime()`에서 음소거와 볼륨을 확인하며, 음소거된 플레이어에게는 `AudioContext`
  자체를 만들지 않습니다. 모션 줄이기 설정은 화면 흔들림만 끄고, 적색 비네팅과 BUST 섬광은 남깁니다.

## 검증

```bash
npm run verify        # 정적 검증 + 빌드 + 런타임 스모크 + E2E
npm run verify:quick  # 브라우저 E2E 없이
npm run verify:static # 브라우저 자체가 필요 없는 티어 (배포 빌드가 쓰는 것)
npm run test:visual   # 시각 회귀만
```

`verify:static`은 lint, CSS 포맷, 단위·스모크 테스트, 인코딩, 텍스트, CSS 토큰, CSS 구조,
그래프, 대사, 밸런스, 압박 시뮬레이션, 엔딩, 아트 예산, 뷰 계약, 상수, 런타임 예산,
내보내기 스키마, 테스트 저장소 키, 시각 베이스라인, Node 핀 20개 검사입니다. `npm test`는 `node --test`로 돌아가므로 어서션 하나가 실패해도 나머지가 모두
실행되고 실패한 것만 이름으로 보고됩니다.

GitHub Actions는 PR에서 `verify:quick`만 돌리고, E2E는 push 또는 `e2e` 라벨에서 실행합니다.
전체 경로 검증(`npm run test:e2e:full`)은 `Full Coverage` 워크플로가 매주 월요일과 수동 실행으로
수행합니다. 시각 회귀는 별도 워크플로이며 베이스라인은 플랫폼별(`linux`, `win32`)로 커밋되어
있습니다.

## 생성물

브라우저로 측정해 만들고 저장소에 커밋하는 파일이 둘 있습니다. 배포 환경에는 Playwright
브라우저가 없으므로 빌드가 이것들을 다시 만들지 않습니다.

- `npm run build:art` — 반응형 이미지 변형. `npm run check:art`가 예산을 지킵니다.
- `npm run build:critical` — 인트로가 실제로 칠하는 CSS. `src/styles/critical.generated.css`에
  쓰고, `vite.config.js`가 이를 인라인한 뒤 전체 스타일시트를 비차단으로 내립니다. 생성 파일은
  잘라낸 스타일시트의 해시를 함께 기록하므로, 스타일이 바뀌면 빌드가 재생성을 요구하며 실패합니다.
  첫 페인트를 막는 바이트: 31.1KB gzip → 7.5KB gzip.

## 배포

Render 배포는 `render.yaml`을 사용합니다.

- Build: `npm ci --include=dev && npm run verify:static && npm run build`
- Publish: `dist`

`VITE_SUPABASE_URL`과 `VITE_SUPABASE_ANON_KEY`는 값 없이 선언되어 있으므로 Render 대시보드에서
설정합니다. 없으면 앱은 텔레메트리와 원격 랭킹을 끈 채로 조용히 동작합니다. 서비스 롤 키는 Render에도
브라우저에도 넣지 않습니다.

배포가 끝나면 배포된 커밋이 최신 `main`인지 확인하고 스모크 검사를 돌립니다.

```powershell
$env:DEPLOY_URL = "https://critical-point.onrender.com"
npm run check:deploy
```

저장소 시크릿 `DEPLOY_URL`을 추가하면 `Deployed Smoke Check` 워크플로가 `Verify` 뒤에 같은 검사를
실행합니다(수동 실행도 가능).

## 원격 랭킹 (선택)

1. `.env.example`을 `.env`로 복사하고 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 채웁니다.
2. 배포 전에 스키마를 적용합니다. `npx supabase link --project-ref <ref>` 후 `npx supabase db push`.
   마이그레이션은 `supabase/migrations/`에 있고, 원격 이력이 유일한 출처입니다. 대시보드 SQL
   에디터로 직접 적용하지 마십시오.
3. 스키마는 공개 플레이테스트용 익명 insert를 허용하고, 텔레메트리 payload 형태·완주 점수 검증과
   시간당 요청 제한(`telemetry_rate_limits`)을 서버에서 겁니다.
4. 익명 읽기는 `playtest_sessions`의 RLS 정책(완주 시즌 행)과 컬럼 단위 grant로 제한됩니다.
   `run_id`, `session_code`, `player_name`, `case_id`, `case_title`, `completed_at`, `summary`만
   읽을 수 있고 `decision_log`, `session_id`, `id`는 읽히지 않으므로 `select *`는 거부됩니다.
   `public_rankings` 뷰는 `security_invoker = true`로 같은 규칙을 상속합니다.
5. 에러 로그 수집용 `app_error_logs`와 피드백용 `playtest_feedback`도 같은 baseline
   마이그레이션에 포함되어 있습니다. 별도로 만들 것은 없습니다.

공개 플레이테스트가 아니라면 전용 프로젝트를 쓰고 키를 주기적으로 교체하십시오. 스테이징은 별도
Supabase 프로젝트를 쓰고, 운영 마이그레이션 전에는 `npx supabase migration list --linked`와
`npx supabase db push --dry-run`으로 먼저 확인합니다.

텔레메트리 보관 기간은 `public.purge_old_telemetry(interval)`로 관리합니다(마이그레이션
`20260907010000_add_telemetry_retention_function.sql`). 30일보다 짧은 기간은 거부하고 기본값은
180일입니다. Supabase Cron 같은 서비스 롤 연결에서만 예약하고 `anon`·`authenticated`에는 권한을 주지
않습니다.

원격 저장을 설정하지 않아도 플레이, 자동 저장, JSON 내보내기, 로컬 랭킹은 그대로 동작합니다.

## 개발 메모

- 개발 도구는 Vite 개발 모드에서 `?debug=1`을 붙이거나 `VITE_ENABLE_DEBUG_TOOLS=true`일 때만
  노출됩니다. 디버그 패널에서 복구 슬롯 복원·삭제, 기록된 사건/장면으로 바로 재현 진입,
  `playtest_sessions`·`playtest_feedback`·`app_error_logs` 읽기 점검을 할 수 있습니다.
  운영 RLS에서 anon 키를 insert 전용으로 두면 저장은 되어도 헬스체크는 `확인 필요`로 뜹니다.
- 에러가 나면 현재 저장본을 `paused`로 남기고 로컬 에러 로그를 기록합니다. 원격 전송은 데이터
  제공 동의가 있는 저장본에서만 하며, 대기열은 온라인 복귀 후 지수 백오프로 재시도합니다.
- 결과 화면의 기본 공유 요약은 `src/state/playtestExport.js`가 조립하며, `playerName`, `log`,
  `sessionId`, `errorLog`, `saveSlots`, `trace`가 빠지는지 단위 테스트로 고정합니다. 원문은
  디버그 진단 로그에만 들어갑니다.
- Windows PowerShell은 유효한 UTF-8 한글을 깨져 보이게 출력할 수 있습니다. 화면에서 깨져 보인다는
  이유로 원고를 고치기 전에 `npm run check:encoding`과 `npm run check:text`를 기준으로 삼으십시오.
- Prettier는 `src/styles`만 관리합니다(`npm run format`). `app.css`가 다시 압축된 형태로
  커밋되는 것을 막기 위한 장치이고, JS/JSX 포맷은 diff 가독성을 위해 강제하지 않습니다.
- ESLint(`npm run lint`)에서 `no-unused-vars`와 `no-undef`는 오류, `react-hooks/exhaustive-deps`와
  `react-hooks/set-state-in-effect`는 경고입니다. 후자는 `AppContent`가 아직 명령형으로 다루는
  효과들에 대한 남은 과제입니다.
