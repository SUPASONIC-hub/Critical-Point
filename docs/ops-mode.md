# 운영 모드 (2026-12-01부터)

11-30 개편까지는 지금처럼 매일 배포합니다(18:50까지). 12-01(화)부터는 이 한 장대로 돕니다.
결정: 2026-11-12 방향 질의 Q4 (1)·Q5 (1). 날짜 계산은 `scripts/ops-calendar.mjs` 한 곳에 있습니다.

## 오늘 무엇을 해도 되나

```
node scripts/ops-calendar.mjs            # 오늘: 배포 요일인지, 다음 비움 가능일, 달력 남은 주
node scripts/ops-calendar.mjs --merge    # 이 갈래를 오늘 병합해도 되는지 (안 되면 exit 1)
node scripts/ops-calendar.mjs --merge --hotfix   # 장애·보안 수정
```

`Funnel`(매일 22:10 KST) 요약 끝에 「운영 달력」 절이 붙고, 달력이 6주 밑이면 경고가 뜹니다.

## 1. 배포는 화·금

- 화면·규칙·글·서버(마이그레이션)가 바뀌는 PR은 **화요일·금요일**에만 병합합니다. 18:50까지.
- 그 밖의 날은 문서·테스트·워크플로·도구만. `--merge`가 파일 목록으로 가릅니다(`src/`, `public/`,
  `supabase/`, 페이지를 만드는 스크립트, `index.html`, `package*.json`이면 배포하는 PR).
- 예외: 접속 불가·저장 깨짐·랭킹 오류·보안 수정은 요일과 상관없이 바로.

## 2. 배포 요일마다 묶음 PR 하나

- 그날 것을 `bundle-MMDD` 하나로 합치고, 갈래 PR은 닫습니다. 묶음에만 `e2e` 라벨.
- main 최신이 아니면 병합하지 않습니다. 마이그레이션은 묶음에 넣되 병합 전 번호 질문 한 번.

## 3. 측정은 배포 날 병합 뒤 한 번

- 레이아웃 측정·스윕·probe는 배포 요일 병합 뒤 한 번, 20 job 이하, after만.
  병합이 배포를 기다리면 probe를 취소합니다.
- 밤새 도는 측정은 배포 전날 밤(월·목)만.

## 4. 매일 자동으로 도는 것

- `Funnel`(funnel·오류·의견·운영 달력, 예산 80% 알람), `Board Reports`(신고), `Test Week`, `Verify Ranking`(23:55 검사·명예 확정),
  `Migration Drift`, 매달 1일 `Workflow Keepalive`.
- Supabase pg_cron 매일 정리(180일 지난 기록·온라인 저장).
- 주간 규칙 달력(`src/gauntlet/weeklyCalendar.js`)은 월요일 0시에 저절로 넘어갑니다.
- 사람이 매일 하는 일: 알람 메일 확인 1분.

## 5. 주간 / 분기

- 주 1회(금요일 배포 뒤): draft PR이 main을 따라가고, 안 쓰는 코드·파일 정리 PR, README·docs 갱신.
- 랭킹 비움과 규칙 숫자 변경은 **분기 첫 월요일**만입니다(2027-01-04, 04-05, 07-05, 10-04).
  비운다면 14일 전부터 시작 화면에 예고합니다. 11-30 비움이 정해진 날 밖의 마지막 비움입니다.

  마이그레이션, 번호 질문 한 번).
