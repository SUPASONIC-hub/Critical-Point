## 상태 업데이트 (2026-09-04, 선택이 질문을 바꾸는 구조로 전환)

플레이 피드백의 핵심은 에러가 아니라 게임성 구조였습니다. 이전 구조는 선택지마다 효과값은
달랐지만, 대부분 같은 다음 장면으로 합류했습니다. 플레이어는 "답을 고르면 새로운 단서나
다른 질문이 열릴 것"이라고 기대하지만, 실제 체감은 같은 질문을 반복하고 점수만 다르게 받는
형태였습니다.

오늘 개선 기준은 다음 네 가지입니다.

- 선택지는 점수 보정 버튼이 아니라 **다음 질문의 종류를 바꾸는 장치**여야 합니다.
- 단서는 결과 화면의 보상이 아니라 **새 선택지와 새 질문을 여는 권한**이어야 합니다.
- 후폭풍은 케이스 종료 설명에만 머물지 않고 **다음 장면의 압박과 최종 질문을 바꿔야** 합니다.
- 마지막 반전은 설명 문단이 아니라 **플레이어가 만든 규칙이 다른 사람에게 적용되는 경험**으로 보여야 합니다.

1차 반영은 CASE 02에 집중했습니다. CASE 02는 "증거 vs 사람" 갈등이 가장 선명해서, 구조 변화의
체감 기준으로 삼기 좋습니다.

- `c2_start`의 세 고정 선택이 이제 서로 다른 본선으로 갑니다.
  - `보고한다` → `c2_route_report`: 절차가 먼저 움직이고, 질문은 "잘못 시작된 절차를 어디서 멈출 것인가"로 바뀝니다.
  - `이민서를 만난다` → `c2_route_person`: 보호가 감정이 아니라 "말할 권한을 어떻게 돌려줄 것인가"로 바뀝니다.
  - `원본을 검증한다` → `c2_route_origin`: 범인 찾기보다 "누가 기록의 공백을 만들었는가"로 바뀝니다.
- 자유입력 성공은 `c2_route_system`으로 들어갑니다. 이 루트는 사건 01의 선택 문장이 유출 파일과
겹친다는 단서를 열어, CASE 02를 단순 유출 사건이 아니라 "플레이어 판단 문장을 복제하는 실험"
가능성으로 전환합니다.
- CASE 02의 최종 질문도 하나로 합류하지 않습니다.
  - 절차 루트는 `c2_final_evidence`
  - 사람 루트는 `c2_final_person`
  - 원본/시스템 루트는 `c2_final_system`
  으로 닫히며, 각자 다른 마지막 딜레마를 묻습니다.
- 기존 케이스 오프닝 분기(`c2_start_people` / `records` / `silence`)는 그대로 유지하되, 오프닝
전용 선택지는 새 본선 루트로 직접 연결되도록 바꿨습니다.
- `getCaseBranchNodes()`는 이제 아무 다중 next 장면이 아니라 `branchId`가 붙은 저작 분기만
카운트합니다. CASE 02 본선 분기가 "숨은 분기 수" 계산을 오염시키지 않게 하기 위한 조치입니다.

이 변경의 목적은 CASE 02 하나를 완성형 샘플로 삼는 것입니다. 이후 CASE 01, 03, 04, 05, FINAL도
같은 방식으로 "선택 → 새 질문 → 다른 최종 딜레마" 구조로 확장해야 합니다. 단순히 장면 수를
늘리는 것이 아니라, 각 선택이 다음 장면의 주어와 갈등 축을 바꾸는지 확인해야 합니다.

## 상태 업데이트 (2026-09-04, 전 케이스 질문 분기 2차 반영)

1차 반영이 CASE 02에 머물러 있으면 플레이어는 여전히 "일부 구간만 달라지고 결국 같은 구조로 돌아온다"고 느낄 수 있습니다. 그래서
이번 2차 반영의 기준은 첫 사건부터 최종장까지 모든 메인 선택이 점수 보정이 아니라 다음 질문의 성격을 바꾸는 것입니다.

- CASE 01은 시작 선택지를 네 갈래 본선으로 분리했습니다.
  - 인력 감축은 `c1_route_layoff`로 가며, 비용 절감보다 누구의 침묵을 비용으로 처리했는지를 묻습니다.
  - 긴급 자금은 `c1_route_funding`으로 가며, 돈이 시간을 사는 대신 설명 권한을 빼앗는 구조를 드러냅니다.
  - 자산 매각은 `c1_route_sale`로 가며, 현금화 과정에서 증거와 고객 데이터가 함께 팔릴 수 있다는 단서를 엽니다.
  - 감사를 먼저 시작하면 `c1_route_investigate`로 가며, 세 해결책이 같은 누락 로그를 공유한다는 첫 반전을 제공합니다.
  - 자유입력 성공은 `c1_route_system`으로 빠져서 준비된 선택지 밖의 문장이 사건의 기준표를 흔드는 숨은 경로가 됩니다.
- CASE 03은 경쟁 입찰을 속도, 증거, 라이벌 공조의 세 질문으로 갈라 놓았습니다. 빠른 승리, 옳은 설명, 경쟁자와의 공동 검증이 서로
  다른 최종 딜레마로 이어져야 합니다.
- CASE 04는 예외 승인, 원칙 고수, 조건부 감사를 각각 다른 질문으로 바꿉니다. 좋은 결과가 규칙을 바꿀 권한을 갖는지, 원칙의 피해를
  누가 책임지는지, 감시 권한을 누가 갖는지가 별도 루트가 됩니다.
- CASE 05는 책임자 지목, 구조 지도 공개, 복구 우선의 세 루트로 나눴습니다. 누가 잘못했는지보다 책임이 흩어지는 방식, 복구가
  증거를 바꾸는 방식, 조용한 피해자가 시스템에서 지워지는 방식을 다룹니다.
- FINAL은 플레이 로그 공개, 외부 폭로, 내부 통제, 자유입력 경로로 갈라집니다. 마지막 반전은 플레이어가 만든 선택 문장이 다음
  참가자의 선택지로 복제되는 경험이어야 합니다.

구현 기준:

- 각 케이스의 시작 선택지는 같은 다음 노드로 합류하지 않고 전용 route node로 이동해야 합니다.
- 각 route node는 다시 전용 final node로 닫히며, final node의 선택만 케이스 aftermath/result로 합류합니다.
- 자유입력 성공은 케이스별 hidden route로 이동해 "선택지 밖 답변"이 실제 구조 변화를 만든다는 보상을 줍니다.
- `getCaseBranchNodes()`는 `branchId`가 붙은 의도된 중간 분기만 세고, 메인 루트 분기는 진행률 계산용 그래프에서 BFS 기반으로
  처리합니다.
- 밸런스 검사는 각 루트가 고유 장점과 비용을 갖는지 확인해야 하며, 한 선택지가 모든 축에서 다른 선택지에 지배당하면 수정합니다.

## 상태 업데이트 (2026-09-04, 단서 기반 역전 선택지 반영)

전 케이스 질문 분기를 넣은 뒤에도, 단서 발견이 단순히 HUD 숫자와 엔딩 조건에만 남으면 플레이어는 "단서를 찾았는데 다음 장면에서
무엇이 달라졌는지"를 체감하기 어렵습니다. 그래서 이번 진행은 단서를 실제 선택지와 질문 경로에 연결하는 것을 기준으로 삼았습니다.

- 모든 케이스에 evidence turnaround node를 추가했습니다.
  - CASE 01: `c1_evidence_turn`
  - CASE 02: `c2_evidence_turn`
  - CASE 03: `c3_evidence_turn`
  - CASE 04: `c4_evidence_turn`
  - CASE 05: `c5_evidence_turn`
  - FINAL: `f_evidence_turn`
- 각 본선 route node에는 "확보한 단서를 대조해 이 질문의 전제를 뒤집는다" 선택지가 추가됩니다.
- 이 선택지는 일반 점수 선택지가 아니라 권한 게이트가 붙은 선택지입니다.

  - FINAL은 `OVERSIGHT`가 필요합니다.

  - 단서 4개 이상과 정당성 55 이상이면 `OVERSIGHT`
- 단서 역전 노드는 기존 route final로 합류하지 않고, 별도 장면에서 사건의 전제를 바꾼 뒤 aftermath/result로 닫힙니다. 즉, 단서는
  "좋은 점수 보너스"가 아니라 "다른 질문을 열 수 있는 권한"으로 작동해야 합니다.

의도한 플레이 감각:

- 플레이어가 단서를 발견하면 다음 루트에서 잠긴 선택지가 눈에 보입니다.
- 잠금이 풀리면 같은 사건이라도 "이 선택이 옳은가"가 아니라 "이 질문의 전제가 조작된 것 아닌가"로 장면이 뒤집힙니다.
- 최종장에서는 충분한 단서와 정당성을 확보한 경우에만, 플레이어의 선택 문장이 다음 참가자의 선택지로 복제되는 구조를 직접 다룰 수
  있습니다.

## 상태 업데이트 (2026-09-04, 이전 케이스 기억 선택지 반영)

단서 기반 역전 선택지가 한 케이스 안에서만 작동하면, 플레이어는 여전히 사건들이 서로 독립된 문제처럼 느낄 수 있습니다. 이번 진행은
"이전 케이스에서 어떤 방식으로 흔들었는가"가 다음 케이스 첫 화면의 선택지로 남도록 만드는 것입니다.

- `getContinuityMemoryChoice()`를 추가해 다음 케이스 시작 노드에서 직전 케이스 로그를 읽습니다.
- 직전 케이스에서 evidence turnaround를 탔으면, 다음 케이스 첫 화면에 단서 대조 선택지가 추가됩니다.
  - 예: CASE 02에서 `c2_evidence_turn`을 탔다면 CASE 03 시작에서 `c3_evidence_turn`으로 바로 들어가는 기억 선택지가 열립니다.
- 직전 케이스에서 자유입력 hidden route를 탔으면, 다음 케이스 첫 화면에 자유응답 문장이 새 시스템 경로로 복제됐는지 확인하는 선택지가
  추가됩니다.
- 직전 케이스에서 일반 route split을 탔으면, 다음 케이스 첫 화면에 그 결정을 현재 사건의 기준표와 대조하는 선택지가 추가됩니다.
- 이 선택지는 기존 authored choice를 대체하지 않고 추가됩니다. 플레이어는 기본 질문을 계속 진행할 수도 있고, 이전 선택의 잔상을
  끌어와 다른 질문으로 시작할 수도 있습니다.

의도한 플레이 감각:

- "지난번에 한 선택"이 결과 요약에서 끝나지 않고 다음 사건 첫 행동으로 되돌아옵니다.
- 단서 루트, 자유입력 루트, 일반 분기 루트가 서로 다른 종류의 다음 선택지를 만듭니다.
- 반복 플레이 시 같은 케이스에 도착해도 이전 사건 로그에 따라 첫 선택지 구성이 달라집니다.

- 이전 케이스 로그가 만든 선택지는 `MEMORY ROUTE`로 표시합니다.
- 단서 대조로 질문의 전제를 뒤집는 선택지는 `EVIDENCE TURN`으로 표시합니다.
- 권한이 필요한 선택지는 기존 잠금 문구와 함께 `FIELD ACCESS` 또는 `OVERSIGHT` 배지를 보여줍니다.

- 새로 열린 선택지가 일반 선택지 사이에 묻히지 않습니다.
- 잠긴 선택지도 "왜 잠겼는지"와 "어떤 권한 계층의 선택지인지"를 함께 보여줍니다.
- 전 케이스에서 만든 변화가 다음 화면에 돌아왔다는 감각을 버튼 레벨에서 먼저 전달합니다.

## 상태 업데이트 (2026-09-04, 루트가 저작 본문을 지나가도록 복구)

분기 배지까지 넣고 나서 그래프를 실제 플레이 순서대로 걸어 보니, 오늘 만든 루트 구조가 사건의

`시작 → 루트 → 루트 파이널 → 후폭풍` 4장면으로 끝났고, 증언 장면과 반응 장면, 분기 디투어는
자유입력에 성공한 사람만 볼 수 있었습니다.

- CASE 01은 특히 심했습니다. 28개 장면 중 12개만 도달 가능했고, `accounting` · `c1_witness` ·
  `payday` · `c1_assembly` · `competitor` · `c1_bargain` · `board` · `c1_verdict`와 각 반응 장면
  15개가 그래프에서 완전히 떨어져 나가 있었습니다.
- CASE 03·04·05는 도달은 가능했지만 자유입력 경로 전용이었습니다. 고정 선택 최장 경로 4장면,
  자유입력 경로 12장면으로 두 배 이상 갈렸습니다.
- CASE 02만 의도한 모양이었습니다. 각 루트가 자기 몫의 저작 장면을 지나 자기 루트 파이널로
  닫힙니다. 그래서 나머지 사건을 CASE 02 모양으로 맞췄습니다.

반영 내용:

- `routeBodyPlans`를 추가해 각 루트에 `entry`(루트가 여는 저작 장면)와 `tail`(그 구간의 마지막
  장면, 여기 선택지가 루트 파이널로 닫힘)을 지정했습니다. 루트마다 다른 구간을 걸으므로 두
  루트가 같은 중간 질문을 반복하지 않습니다.
  - CASE 01: 감사 → `accounting`, 감축 → `payday`, 매각 → `competitor`, 자금 → `board`,
    자유입력 → `c1_branch_people`
  - CASE 03: 증거 → `c3_split`, 속도 → `c3_score`, 라이벌 → `c3_trap`, 자유입력 → `c3_branch_signal`
  - CASE 04: 예외 → `c4_offer`, 감사 → `c4_leak`, 원칙 → `c4_vote`, 자유입력 → `c4_branch_exception`
  - CASE 05: 지도 → `c5_map`, 책임 → `c5_blame`, 복구 → `c5_collapse`, 자유입력 → `c5_branch_owner`
  - FINAL: 로그 → `f_archive`, 폭로 → `f_confront`, 통제 → `f_branch_witness`
