## 상태 업데이트 (2026-09-03, 설계 감사 반영)

`docs/design-audit-2026-09-03.md`의 18개 발견을 P-2(번들 분할)를 제외하고 전부 적용했습니다.

- **G-1·G-2 자원 재설계.** 1번 고정이 모든 축에서 이기던 구조를 깼습니다. 연결·반응 장면의
  효과표를 다시 썼고, 사람 우선은 현금과 시간을 실제로 잃고, 절차 우선은 누군가를 기다리게
  하며(`humanCost`), 이익 우선만 `fatigue`를 되돌려 줍니다. `humanCost`는 선택지의 46%,
  피로 회복 선택지는 44개입니다. `scripts/check-balance.mjs`가 이 상태를 고정합니다.
- **N-1·N-2·N-3 장면 다양화.** 반응 장면이 부모 장면의 효과·대사를 재사용하지 않고 자체
  테이블을 갖습니다(고유 효과 벡터 83%). 케이스마다 그 사건에서만 가능한 네 번째 선택지를
  하나씩 넣었고, 숨은 분기의 부착 위치를 케이스별로 다르게 했으며 두 곳은 자원/직전 결과로
  조건화했습니다(`getBranchDetourBypass`).
- **U-1·U-2·U-3·U-4 화면.** 선택지 위에 고정되는 자원 레일을 추가하고, 작전 브리프와 선택지
  카드의 보조 문장을 기존 "판단 근거" 토글 뒤로 옮겼습니다. 효과 칩은 방향과 함께 크기를
  3단계 기호로 표시하고, `humanCost`/`fatigue` 상승은 이제 붉게 표시됩니다. 자유입력 신호는
  최소 24자와 문장 구조를 요구합니다.
- **G-3·G-4·G-5 점수와 관문.** 버스트 점수의 최대 비중을 응답 리듬(0.24 → 0.08)에서 압박
  아래의 기준 유지(0.28)로 옮겼고, 압박 대응은 진폭이 아니라 회수를 봅니다. 단서 조건을
  넓히고 마지막 사건에서 한 번 회수할 수 있게 했으며, 상위 권한 요구를 5개에서 4개로
  낮췄습니다. 사건이 단서 없이 닫히면 그 사실을 즉시 알립니다. 결정 윈도우는 15초마다
  누진 과금합니다.
- **P-1 성능.** 초 단위 카운트다운을 `src/state/decisionClock.js`의 외부 스토어로 옮겼습니다.
  루트는 15초 단위 phase만 구독하고, 초 단위로 다시 그리는 것은 시계를 출력하는 두 컴포넌트
  뿐입니다. `decisionForecasts`, `riskPressureDrivers`, 장면 챌린지, 선택 리더는 메모이즈했습니다.
- **O-1·O-2·O-3·P-3 운영.** 소스를 덮어쓰는 일회성 추출 스크립트 두 개를 삭제하고,
  `render.yaml`에 `envVars`(sync: false)와 `assets/*` 불변 캐시 헤더를 선언했습니다. 랭킹은
  같은 익명 이름 대신 판단 유형과 실행 번호로 구분합니다. 모바일 플레이·결과 화면 시각
  기준선과 모바일 레이아웃 예산 테스트를 추가했습니다.

**미적용: P-2(번들·CSS 분할).** 두 갈래 모두 이번 범위 밖의 구조 변경이 필요합니다.
`play.css`를 지연 로드하면 `src/styles/app.css`가 문서화하고 `check-css-structure`가 지키는
캐스케이드가 뒤집힙니다(`extensions.css`가 뒤에 와야 하는데 지연 청크가 그 뒤에 붙습니다).
케이스별 노드 모듈의 동적 import는 장면 그래프를 비동기로 만들어야 하는데, 앱·스크립트·
테스트가 모두 동기로 읽습니다. 감사 문서의 의존 순 작업 큐도 같은 이유로 P-2를 빼고 있습니다.

세이브 필드 `timerPenaltyApplied`(boolean)는 `timerPenaltyCount`(number)로 바뀌었고,
기존 세이브는 `normalizeTimerPenaltyCount`가 그대로 이어받습니다.

## 상태 업데이트 (2026-09-03, P-2 재측정과 이미지 최적화)

P-2가 제안한 두 가지 방법을 모두 만들어 재보고, P-2가 근거로 든 세 항목 중 실제로 무게를
지고 있던 것을 고쳤습니다.

**적용: 그리는 크기에 맞춰 이미지를 내려받습니다.** 키비주얼은 1,672px 파일 하나로 인트로
배경과 히어로에 동시에 쓰여, 356px 슬롯을 그리는 휴대폰이 146KB를 받고 있었습니다. 장면·엔딩·
키비주얼 10장에 480px과 960px 변형을 추가하고 배경(`image-set`), 히어로, 플레이 장면, 엔딩
비주얼이 화면 폭과 픽셀 밀도로 고르게 했습니다. 변형은 Chromium 자체 webp 인코더로 만들었으므로
이미지 툴체인이 필요 없습니다.

```
첫 로드      데스크톱 873KB → 776KB      휴대폰 890KB → 744KB
키비주얼     146KB → 49KB(데스크톱) / 17KB(휴대폰)
플레이 화면  데스크톱 326KB → 194KB      휴대폰 336KB → 86KB
```

`npm run check:art`가 변형 존재와 용량 예산을 지킵니다.

**미적용: CSS 지연 청크.** `play.css`를 화면 청크로 옮기면 `index.css`가 155KB → 102KB
(gzip 27.3 → 19.1KB)로 줄어듭니다. 로드 순서로는 캐스케이드를 옮길 수 없어(`extensions.css`가
뒤에 와야 하는데 지연 청크가 그 뒤에 붙습니다) `@layer`로 만들어 봤습니다. 그런데 캐스케이드
레이어는 순서뿐 아니라 **명시도보다 우선**하므로, 지금까지 명시도로 결정되던 충돌이 조용히
뒤집힙니다. `.intro p { font-size: 20px }`(base)가 `.play-style-unlock { font-size: 12px }`
(extensions)에 지는 식으로 인트로에서만 계산 스타일 7건이 바뀌었습니다. gzip 8KB를 위해
검증되지 않은 캐스케이드를 받아들일 수 없어 되돌렸습니다. 제대로 하려면 다섯 파일을 순서에
의존하지 않는 하나의 집합으로 평탄화하거나, 화면별 CSS를 만들고 규칙 단위 동등성을 증명하는
빌드 단계가 필요합니다.

**미적용: 장면 그래프 지연.** `src/nodes/`, `gameData.js`, `gameDialogue.js`의 한국어 문자열을
전부 스텁으로 바꾸면 진입 청크가 348KB → 261KB(gzip 115.7 → 85.2KB)가 됩니다. 30KB는 실제
이득이지만, 그래프는 `AppContent`와 검증 스크립트 두 개, e2e 헬퍼가 모듈 최상위에서 동기로
읽고 있고 `AppContent`가 인트로를 그립니다. 그래프를 비동기로 바꾸고 그 독자들을 전부 다시
쓰기 전에는 아무것도 미룰 수 없습니다. 지금의 30KB가 정당화하는 것보다 크고 위험한 변경입니다.

## 상태 업데이트 (2026-09-03, 2차 감사 9건 반영)

  devDependency라 새 의존성은 없습니다.

`check-balance`의 다섯 번째 규칙은 "각 열이 최소 한 자원에서 최고"에서 "어떤 열도 파레토
지배당하지 않음"으로 바꿨습니다. 자원이 100에서 상한에 걸리면 동점이 생기는데, 그 동점을

## 상태 업데이트 (2026-09-03, 3차 감사 반영)

`docs/design-audit-2026-09-03-round3.md`의 8건 중 7건을 반영했습니다.

- **E-1 실패 엔딩이 실제로 납니다.** `collapse`는 압박 82 또는 사람 피해 70을 요구했는데
  케이스마다 자원이 초기화되어 한 케이스의 최대치가 33·31이었습니다. 이제 엔딩 판정이
  시즌을 읽습니다 — 케이스별 최종 사람 피해의 합과 케이스별 최고 압박. 케이스 요약에
  `finalHumanCost`·`peakRiskPressure`를 실어 보냅니다. 임계값은 최고 압박 52 또는 시즌
  사람 피해 150이고, 비용을 계속 넘기는 런과 끝까지 사람을 지키다 소진되는 런 양쪽에서
  납니다.
- **E-2 FIELD PACT가 납니다.** 조건을 `trust - legitimacy >= 20`으로 바꾸고, 마지막 사건에
  믿음을 공정함으로 사는 유일한 경로(`f_confront_pact`)를 넣었습니다.
- **E-3 기본 엔딩이 런을 읽습니다.** 네 번 중 한 번이 도달하는데 한 줄이었습니다. 믿음·
  공정함·현금 중 무엇을 쥐고 끝냈는지에 따라 세 가지로 갈립니다.
- **D-1 죽은 선택지 0개.** 같은 장면에서 모든 축에 지던 11개에 각자의 강점을 주고,
  `check-balance`가 케이스 열뿐 아니라 장면 안에서도 지배를 검사합니다.
- **D-2 모든 선택지가 고유 대사를 갖습니다.** 오프닝 45줄을 새로 써서, 고정 선택지 320개
  전부가 고유한 voice와 echo를 갖습니다(274 → 320).
- **U-1·U-2 확정 콘솔.** 관찰자 반응과 예상 자원을 접고, 모바일에서 제목 행과 버튼 세로
  배치를 없앴습니다. 356px → 213px, 덮이는 카드 2장 → 1장, 열릴 때 늘어나는 여백 60dvh →
  34dvh.

`npm run check:endings`를 추가했습니다. 6,000회 랜덤 시즌을 돌려 아홉 엔딩 중 하나라도
도달 불가능해지면 실패합니다 — 두 개를 몇 달간 숨겼던 종류의 버그입니다.

**미반영: M-1(인트로를 AppContent에서 분리).** 진입 청크 소스 453KB 중 AppContent 98KB,
gameData 62KB, gameDialogue 22KB입니다. AppContent가 인트로를 그리는 한 그 import 그래프가
첫 로드에 필요하므로 아무것도 미룰 수 없습니다. 플레이·결과 파생을 인트로 이후에 마운트되는
런타임 컴포넌트로 옮기고 셸에는 시작 전 상태만 남기는 작업이며, 다른 작업 안에 끼워 넣을
크기가 아닙니다. 회수되는 gzip 30KB가 긴 작업 끝에 서둘러 할 이유가 되지 못합니다.
