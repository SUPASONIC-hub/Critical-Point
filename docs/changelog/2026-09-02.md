## 상태 업데이트 (2026-09-02, 원격 텔레메트리 장애 수정)

Supabase 로그에서 실제 동작 장애 두 건을 확인하고 `supabase/migrations/20260902061041_fix_telemetry_rate_limit_and_ranking_view.sql`로 수정했습니다.

- `42702 column reference "actor_key" is ambiguous` — `validate_telemetry_insert()`가 PL/pgSQL 변수 `actor_key`, `request_count`, `window_started_at`을 선언했는데 이는 `telemetry_rate_limits`의 컬럼명과 동일합니다. `on conflict (actor_key)`의 인덱스 추론과 `returning ... into` 대상이 변수/컬럼 중 무엇인지 해석되지 않아 BEFORE INSERT 트리거가 실패했고, 세 테이블의 **모든 원격 텔레메트리 쓰기가 차단**됐습니다. 변수에 `v_` 접두사를 붙여 해소했습니다. `window_started_at`은 대입만 되고 읽히지 않던 미사용 변수라 제거하고 `returning request_count into v_request_count`로 좁혔습니다.
- `42501 permission denied for table playtest_sessions` — `public_rankings` 뷰가 `security_invoker = true`인데 `revoke select on public.playtest_sessions from anon`이 함께 적용돼 있어, anon이 뷰를 통해 기반 테이블에 접근하는 순간 권한 오류가 났습니다. 랭킹 화면 조회(`fetchLeaderboard`)와 디버그 헬스체크가 모두 이 경로입니다. 뷰 자체가 보안 경계(완주 시즌 행만, `decision_log` 제외)이므로 `security_invoker = false`로 되돌려 소유자 권한으로 실행되게 했습니다. anon의 원본 세션 행 직접 읽기는 계속 차단됩니다.

로컬에 Docker가 없어 `supabase db reset`으로 실행 검증은 하지 못했습니다. 정적 대조로 함수 본문 100줄 중 의도한 6곳 외 변경이 없음을 확인했습니다.

베이스라인은 이미 적용된 상태이므로 수정하지 않고 새 마이그레이션으로 분리했습니다.

## 상태 업데이트 (2026-09-02, 랭킹 노출 규칙을 테이블로 이동)

Supabase Security Advisor가 `public.public_rankings`를 `Security Definer View`(Critical)로 지적했습니다. 앞선 수정에서 anon에게 `playtest_sessions` SELECT 권한이 없어 뷰를 definer로 되돌린 결과였습니다. `supabase/migrations/20260902063941_rankings_rls_instead_of_definer_view.sql`로 구조를 바꿔 경고를 우회가 아닌 개선으로 해소했습니다.

- 행 필터를 RLS 정책으로 내렸습니다. 완주 시즌 행이면서 `burstScore`가 0~100 범위의 정상 수치인 행만 anon이 읽습니다. 뷰의 `where` 절과 동일한 조건입니다.
- 컬럼 필터를 컬럼 단위 GRANT로 내렸습니다. `run_id`, `session_code`, `player_name`, `case_id`, `case_title`, `completed_at`, `summary` 7개만 허용하므로 `decision_log`, `session_id`, `id`는 계속 읽을 수 없고 `select *`도 거부됩니다.
- `public_rankings`를 `security_invoker = true`로 되돌렸습니다. 클라이언트 코드 변경은 없습니다.
- 노출되는 데이터는 이전과 동일합니다. 달라진 것은 제약이 뷰 본문이 아니라 테이블에 붙는다는 점이고, 앞으로 추가되는 어떤 리더도 같은 제한을 받습니다.

원격 DB에 `db push`로 적용한 뒤 REST 프로브 6건으로 실동작을 확인했습니다: 랭킹 뷰 읽기 200, 허용 컬럼 읽기 200, `decision_log`/`session_id`/`select *` 각각 42501 거부, insert 트리거 정상(P0001 payload 검증 도달).
