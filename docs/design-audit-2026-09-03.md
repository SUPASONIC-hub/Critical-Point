## 먼저 알아야 할 것

개별 결함보다 먼저, 게임의 중심 주장과 실제 수학이 어긋나 있다. `board` 장면은 "완벽한
선택지는 없다"고 말하지만, 전체 그래프를 시뮬레이션하면 **첫 번째 선택지만 계속 고르는
전략이 모든 자원 축에서 동시에 최선**이다. 트레이드오프가 성립하지 않으면 서스펜스·반전·
랭킹이 모두 그 위에서 헐거워진다. 나머지 발견은 대체로 이 한 가지의 파생이거나, 그것을
가리고 있는 표면이다.

## 게임성 (G · 5건)

### G-1 【치명】 1번 선택지가 지배 전략이다

전체 노드 순서를 따라 "항상 N번째 선택지"를 세 가지로 시뮬레이션했다. 1번 고정은 믿음·
공정함이 만점, 현금은 90, 사람 피해는 0으로 끝난다. 어느 축에서도 대가를 치르지 않는다.
딜레마가 수학적으로 존재하지 않는다.

```
99회 판단 후 최종 자원 (time·capital·trust·legitimacy·humanCost·fatigue)
  항상 1번  t0  C90  T100  L100  H0   f100  압박 44
  항상 2번  t0  C0   T100  L100  H62  f100  압박 82
  항상 3번  t9  C88  T0    L100  H8   f100  압박 44
```

**고칠 곳** — 같은 축을 동시에 올리는 선택지를 없앤다. 최소한 1번 계열에 `humanCost`
또는 `capital` 실비용을 붙여, "사람을 지키는 판단"이 현금이나 시간 중 하나를 반드시
포기하게 만든다.

### G-2 【치명】 자원 6개 중 4개가 사실상 자원이 아니다

`fatigue`는 회복 수단이 전혀 없는 단방향 래칫이고, `time`은 거의 소모만 된다. 둘 다 판단
20~30회 안에 한계치에 붙은 뒤 게임이 끝날 때까지 움직이지 않는다. `legitimacy`는 순증
+1,050으로 그냥 차오르고, 게임의 주제인 `humanCost`는 선택지의 16%에만 등장한다. 실제
양방향 거래가 되는 것은 현금과 믿음 둘뿐이다.

```
298개 선택지 중 등장 비율 / 전체 순증
  legitimacy  81%   +1050      fatigue  80%   +1260  (감소 0건)
  trust       74%   + 113      capital  47%   + 200
  time        40%   - 655      humanCost  16%   -   6
```

**고칠 곳** — 피로 회복 행동(위임·휴식·인계)을 선택지로 도입하고, `legitimacy`를 올리는
선택지 수를 줄인다. `humanCost`는 최소 40% 선택지에 붙여야 "누가 비용을 지는가"가 실제
기계가 된다.

### G-3 【높음】 점수가 판단 내용이 아니라 조작 습관을 잰다

`momentumScore`의 24%는 응답 시간, 24%는 인지 유형의 다양성, 24%는 압박의 진폭이다.
8~28초에 답하면 리듬 만점이고, 압박을 크게 흔들수록 적응 점수가 오른다. 무엇을
선택했는지는 점수에 직접 들어가지 않는다. 랭킹 상위를 노리는 플레이어의 최적해는
"10초 세고, 유형을 번갈아 고르고, 위험을 일부러 출렁이게 한다"가 된다.

```
momentumScore = rhythm·.24 + cognition·.24 + pressureAdapt·.24
              + reflection·.20 + challenge·.08 − exploitPenalty
rhythm:        8~28초 → 100점 / 4~8초 → 70 / 45초 초과 → 38
pressureAdapt: riskSwing(|델타| 합) × 3  ← 진폭이 클수록 가점
```

**고칠 곳** — 리듬 가중치를 크게 낮추고, 자기 판단의 일관성(같은 원칙을 압박 아래서도
유지했는가) 또는 선언한 우선순위와 실제 선택의 일치도를 점수 축으로 바꾼다.

### G-4 【높음】 최고 엔딩이 놓치면 되돌릴 수 없는 숨은 관문 뒤에 있다

단서는 케이스당 정확히 1개, 시즌 전체 최대 6개다. 그런데 상위 엔딩과 `OVERSIGHT` 권한은
5개를 요구한다. 단서 획득 조건은 특정 장면에서 `challengeMatch`가 맞고 동시에 위험 +2
이상이거나 12초 이내 응답일 때뿐이며, 케이스를 벗어나면 영구 소실된다. 플레이어에게는 이
규칙도, 놓쳤다는 사실도 고지되지 않는다.

```
단서 총량 6 (케이스당 1)  ·  상위 엔딩 요구 5  ·  허용 실패 1회
조건: challengeMatch && (riskDelta ≥ 2 || responseTimeSec ≤ 12)
숫자 예측 UI 해금: evidenceCount ≥ 3
```

**고칠 곳** — 케이스당 단서를 복수로 두거나 후반 회수 경로를 만들고, 놓친 시점에 "이번
사건의 기록 하나가 닫혔습니다"를 즉시 표시한다.

### G-5 【보통】 제한 시간이 한 번만 물고 끝난다

45초 창이 닫히면 `time −2 / fatigue +3`을 한 번 물리고 `timerPenaltyApplied`가 잠긴다.
이후에는 무한정 고민해도 추가 비용이 없다. 압박을 연출하지만 실제로는 물지 않는다.

**고칠 곳** — 초과 시간에 비례해 계속 과금하거나, 창이 닫히면 선택지 하나가 실제로
사라지게 한다.

## 이야기와 반전 (N · 3건)

### N-1 【치명】 장면 99개가 사실상 세 가지 선택의 반복이다

연결 장면과 반응 장면은 `authoredSceneChoiceEffects` 템플릿 18종을 공유하고, 그 18종은
모두 같은 3분할이다 — 사람 우선 / 절차 우선 / 이익 우선. `accounting`과 `c1_witness`는
같은 효과 배열을 그대로 참조한다. 표면 문장은 다르지만 결정은 같아서, 케이스 01만 지나면
나머지는 자동 조종이 된다.

```
효과 벡터   298개 → 고유 184  (38% 중복)
선택지 문구 342개 → 고유 262  (23% 중복)
```

**고칠 곳** — 템플릿 3분할을 깬다. 케이스마다 그 사건에서만 가능한 네 번째 축(예: 케이스
02는 "지목된 사람과 거래한다")을 하나씩 넣는 것이 가장 싼 해법이다.

### N-2 【높음】 주인공 대사 54줄이 바로 다음 장면에서 그대로 반복된다

`getAuthoredSceneCopy`가 반응 장면에 부모 연결 장면의 대사를 그대로 넘긴다.
`c1_witness`에서 고른 문장이 곧바로 `c1_witness_reaction`에도 등장한다. 반복 중에서도
가장 눈에 띄는 인접 반복이다.

```
choiceVoiceLines  209줄 → 고유 155   (중복 54)
echoReplies       210줄 → 고유 156   (중복 54)
c1_witness_choice_1 === c1_witness_reaction_choice_1  → true
```

**고칠 곳** — `authoredSceneChoiceCopy`에 `reaction` 키를 실제로 채운다. 코드는 이미
`copy.reaction ?? copy`로 그것을 기다리고 있는데 아무도 정의하지 않았다.

### N-3 【보통】 숨은 분기가 항상 "첫 번째 선택지"에 붙어 있다

`authoredBranchPlans`는 케이스마다 정확히 한 노드의 `choiceIndex 0`을 2장짜리 우회로로
바꾼다. 규칙이 예외 없이 같아서, 두 번째 플레이의 플레이어는 "1번을 고르면 숨은 장면"이라는
메타를 학습한다. G-1과 겹치면 1번 고정 전략이 콘텐츠 보상까지 독점한다.

**고칠 곳** — 분기 부착 위치를 케이스마다 다르게 하고, 최소 두 곳은 자원 상태나 이전
케이스 결과로 조건화한다.

## UI · UX와 정보 직관성 (U · 4건)

### U-1 【치명】 모바일에서 한 번 판단하는 데 화면 7장을 스크롤한다

Pixel 7 뷰포트(390×844)에서 플레이 화면 전체 높이를 실측하면 5,775px이다. 선택지는 약
45% 지점에서 시작하고, 자원 상태판은 선택지보다 *아래*에 있다. 즉 무엇을 걸고 고르는지
보려면 고른 뒤에 스크롤해야 한다.

```
플레이 화면 높이 5,775px / 뷰포트 844px = 6.8 화면
선택 패널 진입점  약 y=2,600 (45%)
자원 상태판       선택지 하단 (약 y=5,000+)
```

**고칠 곳** — 모바일에서 자원 상태를 상단 고정 바로 올리고, 브리핑 패널 다수를 기본
접힘으로 바꾼다. 선택지는 첫 화면 안에 들어와야 한다.

### U-2 【높음】 선택지 앞에 조언 패널 25개가 먼저 온다

`PlayScreen.jsx`에서 선택 패널은 576번째 줄, 그 위에 조건부 섹션이 25개 쌓여 있다. 관계
그래프, 라이벌 개입, 증거 복구, 가설 처리, 미드보스, 자율 행동 신호가 모두 결정 이전에
놓인다. 결정의 무게가 주변 정보에 희석된다.

```
PlayScreen  className 149개  ·  <section>/<details> 33개
선택 패널 위치  line 576  (그 위 섹션 25개)
선택지 카드 한 장  최대 12개 하위 요소 × 3~4장
```

**고칠 곳** — 장면 → 선택지를 기본 화면으로 두고, 보조 패널은 "판단 근거 열기" 한 개의
서랍 뒤로 옮긴다. 이미 있는 `상황 읽기 / 말 고르기 / 기록 확정` 3단 탭이 그 골격이다.

### U-3 【높음】 선택지에 크기가 표시되지 않는다

`formatEffectChip`은 "믿음 상승 / 현금 소모"만 출력하고 수치를 버린다. `capital +22`와
`capital +8`이 화면에서 구분되지 않는다. 게다가 상위 3개만 보여주므로 나머지 효과는
사라지고, 정확한 숫자는 단서 3개를 모아야 확정 콘솔에서 열린다.

```
const formatEffectChip = ([key, value]) =>
  `${resourceMeta[key]?.label} ${value > 0 ? "상승" : "소모"}`   ← 크기 소실
표시 개수 .slice(0, 3)  ·  숫자 해금 evidenceCount ≥ 3
```

**고칠 곳** — 숫자를 숨기더라도 크기는 3단계 기호(▲ / ▲▲ / ▲▲▲)로 항상 보여준다. 방향만
알고 크기를 모르면 트레이드오프 판단 자체가 불가능하다.

### U-4 【보통】 자유 입력 평가가 키워드 4개 정규식이다

`getFreeTextSignals`는 이해관계자·교환조건·근거·위험 네 버킷을 정규식으로 검사하고, UI가
각 버킷의 힌트를 그대로 노출한다. "직원 대신 확인 위험" 여덟 글자면 네 신호가 모두 켜지고
반영 점수 최대치를 받는다.

**고칠 곳** — 최소 길이와 문장 수 조건을 걸고, 힌트는 제출 후 피드백으로 옮긴다. 점수보다
"당신이 쓴 조건이 다음 장면에 인용된다"는 반영이 훨씬 강한 보상이다.

## 속도와 안정성 (P · 3건)

### P-1 【높음】 1초마다 화면 전체가 다시 그려진다

제한 시간 `setInterval`이 매초 `decisionSeconds`를 바꾸고, 그때마다 `AppContent`가 150개
키짜리 `playView` 객체를 새로 만든다. `useCallback` 0개, `React.memo` 0개라 하위 트리는
항상 전부 재렌더된다. `decisionForecasts`는 메모이즈되지 않아 선택지마다 예측 계산이 매초
반복된다.

```
AppContent   useState 25 · useMemo 20 · useCallback 0 · useRef 18
playView     매 렌더 새 객체 리터럴 (약 150 키)
decisionForecasts / riskPressureDrivers  → useMemo 없음, 매초 재계산
재렌더 빈도  1 Hz × 45초 × 약 65 노드
```

**고칠 곳** — 타이머를 자체 구독 컴포넌트로 분리해 초 단위 상태가 루트에 닿지 않게 하는
것이 단일 최대 효과다. 그다음 `decisionForecasts`를 `useMemo`로 감싼다.

### P-2 【보통】 첫 화면이 필요 없는 것까지 받는다

화면은 `lazy`로 잘 분리되어 있지만, CSS 154KB가 단일 번들이라 인트로에서 플레이 화면용
`play.css`(3,100줄)까지 전부 받는다. 메인 청크 332KB에는 6개 케이스의 모든 대사와 노드가
들어 있어, 케이스 01만 필요한 시점에 시즌 전체 텍스트를 내려받는다.

```
index.js  332KB (gzip 111)   react-vendor 192KB
index.css 154KB (gzip 27) — 전부 선행 로드
public/   1.5MB  ·  키비주얼 webp 150KB + jpg 131KB
```

**고칠 곳** — 케이스별 노드 모듈을 동적 import로 돌리고, 화면별 CSS를 해당 청크에 붙인다.

### P-3 【보통】 가장 복잡한 화면에 시각 회귀 기준선이 없다

시각 기준선은 인트로 데스크톱·인트로 모바일·플레이 데스크톱 세 장이다. 정작 가장 조밀하고
U-1이 지적한 문제가 있는 **모바일 플레이 화면**과 결과 화면에는 기준선이 없다.

**고칠 곳** — 모바일 플레이와 결과 화면 스냅샷을 추가한다. 레이아웃 회귀를 잡는 가장 싼
그물이다.

## 운영 (O · 3건)

### O-1 【높음】 소스를 덮어쓰는 일회성 스크립트가 남아 있다

`scripts/extract-play-result-screens.mjs`는 예전 `src/App.jsx`에서 화면을 뽑아내던
마이그레이션 도구다. 지금 실행하면 `ResultScreen.jsx`와 `PlayScreen.jsx`를 통째로
덮어쓴다. 현재는 마커를 못 찾아 예외로 멈추지만, 들고 있는 별칭 목록은 이미 실제 화면과
어긋나 있다.

**고칠 곳** — 삭제한다. 역할은 끝났고 남아 있을 이유가 없다.

### O-2 【보통】 render.yaml이 환경변수와 캐시 헤더를 선언하지 않는다

현재 `render.yaml`에는 `envVars`도 `headers`도 없다. `VITE_SUPABASE_*`가 대시보드에만
있으면 설정이 코드에 남지 않아 서비스를 다시 만들 때 텔레메트리와 랭킹이 조용히 꺼진다.
해시가 박힌 `assets/`에 장기 캐시 헤더도 걸려 있지 않다.

```
render.yaml  envVars: 없음  ·  headers: 없음  ·  autoDeploy: true
telemetryEnabled = Boolean(SUPABASE_URL && SUPABASE_ANON_KEY)  ← 미설정 시 무음 비활성
```

**고칠 곳** — `envVars`에 `sync: false`로 키 이름만 선언해 존재를 코드에 남기고,
`assets/*`에 `immutable` 캐시 헤더를 추가한다.

### O-3 【보통】 랭킹의 모든 타인이 "익명 분석관"이다

`normalizeEntry`는 로컬 행이 아닌 모든 원격 행의 이름을 `"익명 분석관"`으로 고정한다.
개인정보 관점에서는 안전하지만, 리더보드가 같은 이름 50줄이 되어 사회적 동기가 사라진다.

**고칠 곳** — 이름 대신 이미 계산되는 `style`과 `league`(BOARD BREAKER · RISK CUTTER 등)를
전면에 세운다. 익명성을 지키면서 구분이 생긴다.
